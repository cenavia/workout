## Ticket: WT-004

**Título:** Implementar middleware de autenticación JWT para proteger endpoints
**Tipo:** [FEATURE]
**Estimación:** 3h
**Prioridad:** Crítica
**Asignado a:** Sin asignar
**Sprint:** Sprint 1

---

### Descripción

Implementar middleware de autenticación JWT que valida tokens en todas las rutas protegidas. El middleware debe verificar la firma del token, su expiración, extraer el user_id del payload y asegurar que cada usuario solo acceda a sus propios recursos (aislamiento de datos).

### User Story Relacionada

**Como** sistema  
**Quiero** validar JWT en todas las rutas protegidas  
**Para** garantizar que solo usuarios autenticados accedan a sus datos

---

### Criterios de Aceptación

- [ ] Middleware de autenticación JWT implementado
- [ ] Todos los endpoints excepto `/api/auth/*` requieren token
- [ ] Validación de firma del token
- [ ] Validación de expiración del token
- [ ] Extracción de `user_id` del payload del token
- [ ] Retorna 401 si el token es inválido o expirado
- [ ] Retorna 401 si no se proporciona token
- [ ] El `user_id` se inyecta en el request para uso en controladores
- [ ] Tests unitarios e integración implementados

### Requisitos No Funcionales

- **Seguridad:** 
  - Validación estricta de firma
  - No exponer detalles de error (solo 401 genérico)
  - Rate limiting en endpoints de auth
- **Performance:** 
  - Validación rápida (< 10ms)
  - Cache de validación si es necesario

---

### Notas Adicionales

- El middleware debe ser reutilizable y configurable
- Considerar diferentes estrategias de error (401 vs 403)
- El user_id extraído se usará para filtrar datos en repositorios
- Revisar estándares de seguridad en `ai-specs/specs/backend-standards.mdc`

    Given que tengo un token JWT con firma inválida
